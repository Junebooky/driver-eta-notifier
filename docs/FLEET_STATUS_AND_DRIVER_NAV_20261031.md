# 차량 운행 상태와 기사 하단 메뉴

기존 PR #40의 배차·이메일·운행일지 구현을 확장한다. 별도 배차 저장소나 운행일지 앱을 만들지 않는다. 작업 시작 시 원격 브랜치 HEAD `8d68a891206730194eb3d2174165a14820911915`와 로컬을 대조했다.

## 상태 기준

차량 관리, PC 빠른 배정, 모바일/PC 예약 상세, 이메일 날짜별 차량 선택은 `/api/fleet/availability`의 `currentStatus`를 사용한다. `isAvailable`은 선택한 일정과의 충돌 여부로 별도 유지한다.

| 상황 | 현재 상태 |
| --- | --- |
| 현재 운행 없음 / 향후 일정만 있음 | 대기 중 |
| 확정 일정의 시작~종료 시간 | 운행 중 |
| 기사 도착·탑승·이동 상태 | 운행 중 (조기 시작·예정 종료 초과 포함) |
| 운행 완료 / 취소 / 실제 시작 없이 예정 시간 종료 | 대기 중 |
| 관리자 정비 설정 | 정비 중 (최우선) |
| 관리자 확인 필요 설정 | 확인 필요 (실제 운행 기록이 있으면 운행 중) |
| 조회 실패 | 확인 불가 / 배정 선택 비활성화 |

일정 시간은 한국 시간 기준이다. 종료 시간이 없으면 시작 후 완료 확인까지 운행 중으로 처리한다. 완료/종료 기록은 그보다 오래된 수동 운행 중 표시를 해제한다. 이후 수동 운행 중 설정은 유지한다. 배차 요청·초안은 운행 중으로 보지 않는다. 이는 일정과 운행 기록에 따른 상태이며 GPS 주행 감지는 아니다.

가용 차량을 먼저, 그 안에서 대기 차량을 먼저 표시한다. 미래 배차를 편집할 때 현재 운행 상태까지 제외하지 않는다. 다일 이메일은 각 날짜의 가용성 교집합을 사용하므로 사용하지 않는 날짜·야간 사이의 다른 예약을 잘못 차단하지 않는다.

화면이 보일 때 8초마다 갱신하고 포커스 복귀·온라인 복귀·화면 재표시·기존 배차 변경 이벤트에도 갱신한다. 다른 기기 간 반영은 다음 조회 시점에 이뤄진다. 서버 오류 후 오래된 가용성을 선택 가능한 상태로 남기지 않는다.

## 하단 메뉴

기존 상단 운행/스케줄 전환을 홈·스케줄·운행일지 하단 메뉴로 이동했다. 참고 이미지의 흰 배경, 검은 아이콘, 아이콘 아래 라벨과 선택된 홈의 채움 아이콘을 따른다. 현재 콕핏 홈, 기존 ScheduleTab, 기존 DrivingLogModal의 페이지 표시 모드를 연결한다.

운행일지의 배차 ID·기사 UUID·제출/임시저장·지도 검색 흐름을 유지한다. 한 번 연 작성기를 탭 전환 시 숨겨 입력 상태를 보존하고, 다른 기사/배차로 바뀌면 기존 범위 키로 다시 연다. 하단 safe-area 여백과 입력/버튼 스크롤 여백을 반영한다. 경비·영수증은 홈의 기존 바로가기로 유지한다.

## 검증

- `npm test`: 37/37 테스트 파일 통과. 상태 시간 경계·자정·조기 시작·종료 초과·완료·정비·현재 상태/배정 가용성 분리·다일 선택 검증 포함.
- `npx tsc --noEmit`, `npm run build`, `git diff --check` 통과.
- 새 상태 헬퍼·하단 메뉴·가용성 hook·신규 테스트 대상 ESLint 통과. 레거시 전체 ESLint 통과를 의미하지 않는다.
- 격리된 인증 제공자를 연결한 프로덕션 HTTP smoke 통과.
- Chromium에서 실제 빌드 UI 검증(API 응답은 격리 fixture): 홈/스케줄/운행일지 전환, 두 탭을 경유한 운행일지 입력 보존, 320/390/1024px 너비의 하단 메뉴·제출 버튼 겹침 및 가로 넘침 검증. 차량 관리 배지의 주기적 대기→운행 중 갱신과 포커스 복귀 시 대기 복귀 확인.
- 기존 실제 Postgres CI 통합 테스트에 일정 배정→공유 가용성 API→기사 운행 시작/완료→대기 복귀, 다른 기사 변경 거절을 추가했다. 실제 DB 실행 결과는 해당 커밋의 CI에서 확인한다.

운영 DB 마이그레이션 적용과 main 병합/배포는 이 코드 변경에 포함하지 않는다. 앞서 준비한 배차·인증·보고 스키마 및 실제 기사 계정 연결이 운영 활성화의 선행 조건이다.
