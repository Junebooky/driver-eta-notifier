## 2. 과업별 상세 기술 분석 및 구현 내역

### 1) 설정창(ProfileModal) 티맵 로고 통일 및 'T' 심볼 좌우 대칭 교정
- **기존 문제점**:
  - `components/ProfileModal.tsx`의 내비게이션 선택 목록에 구형 붉은색 단색(`bg-[#EF4444]`) 티맵 아이콘이 잔존하여 메인 헤더의 신규 BI와 불일치 발생.
  - 기존 인라인 SVG 패스에서 상단 가로 바(Crossbar)의 중심축이 우측으로 치우쳐 좌측 꼬리가 우측 날개에 비해 짧아 보이는 시각적 비대칭 존재 (`x=11.0` 기준 좌 7.5 unit vs 우 9.5 unit).
- **개선 및 교정 내역**:
  - `ProfileModal.tsx` 내비 선택 영역에 메인 화면과 동일한 순백색 원형 바탕(`bg-white border border-slate-200 shadow-xs`)과 `#E11D48` → `#9333EA` → `#06B6D4` 인라인 리니어 그라데이션 적용.
  - **좌우 대칭 정밀 교정**:
    * 24x24 viewBox 중심(`x=12.0`)을 기준으로 스템(기둥) 폭 5.2 unit (`x=9.4` ~ `x=14.6`), 좌측 날개 폭 5.9 unit (`x=3.5` ~ `x=9.4`), 우측 날개 폭 5.9 unit (`x=14.6` ~ `x=20.5`)으로 완벽한 수학적·시각적 좌우 대칭 패스 설계.
    * 적용 패스: `d="M3.5 6.25C3.5 4.8 4.7 4 6 4H18C19.3 4 20.5 4.8 20.5 6.25C20.5 7.7 19.3 8.5 18 8.5H14.6V19.5C14.6 20.9 13.5 22 12 22C10.5 22 9.4 20.9 9.4 19.5V8.5H6C4.7 8.5 3.5 7.7 3.5 6.25Z"`
    * `components/Header.tsx`와 `components/ProfileModal.tsx` 모두에 동일한 정밀 대칭 패스 일괄 반영.

### 2) 출발지/목적지 변경에 따른 실시간 ETA 및 보고 문구 동적 연동 (Data Binding Fix)
- **근본 원인 분석**:
  1. **초기 렌더링 지연 및 하드코딩 폴백**: `routeEstimate` 초기 상태가 `null`인 상태에서 기본 거점 선택 시, API 응답 수신 전까지 `62.4km / 70분` 하드코딩 기본값이 노출되거나 클립보드에 담기던 현상.
  2. **Vercel 서버 타임존(UTC)과 클라이언트 타임존(KST) 불일치**: Next.js App Router API Route(`/api/route`)가 실행되는 서버 환경은 UTC 기준이므로, 서버에서 생성된 `etaFormatted` 시각이 한국 현지 시각보다 9시간 느리게 산출되는 문제.
  3. **거점 선택 및 스왑 인터랙션 시 비동기 지연**: 거점 칩 터치 및 맞교환(⇄) 시 `useEffect`에만 의존하여 즉각적인 경로 재계산 트리거가 누락되거나 지연되던 구조.
- **해결 조치**:
  1. **즉시 연산 초기화**: `app/page.tsx` 마운트 시 하버사인 추정치를 즉시 초기값으로 주입하여 컴포넌트 첫 프레임부터 실제 선택된 거점 기준의 거리와 소요시간이 바인딩되도록 개선.
  2. **클라이언트 동적 시계 연산 (`now + duration`)**:
     * `/api/route`로부터 소요 시간(`durationMinutes`)과 거리(`distanceKm`)를 수신한 즉시, 브라우저 로컬 시계(`new Date()`)를 기준으로 실제 도착 예정 시각(`HH:mm`)을 실시간 연산하여 KST 시차 문제를 원천 해결.
  3. **즉각적 API 재호출 트리거**:
     * 거점 칩 탭(`handleSelectPreset`) 및 맞교환(`handleSwapOriginDestination`) 핸들러 내부에서 변경된 좌표로 `fetchRouteEstimate`를 즉시 직접 호출하여 딜레이 없이 백엔드 API 통신 수행.
  4. **보고 문구 데이터 파이프라인 완전 연동**:
     * `utils/reportGenerator.ts`의 `GenerateReportParams`에 `distanceKm` 및 `durationMinutes` 필드를 추가하고, `[출발/이동]` 템플릿에 실시간 이동거리와 소요시간, 동적 ETA 시각이 100% 반영되도록 업데이트.
     * `ActionPanel.tsx`의 '카카오톡 단톡방 보고' 버튼 클릭 시에도 현재 활성화된 `origin`, `destination`, `routeEstimate`의 실시간 값이 오차 없이 포맷팅되어 클립보드에 주입됨.

### 3) 카카오톡 메시지 전송 파이프라인 점검 및 실무 최적화
- **기술 분석 (모바일 브라우저/PWA 보안 제약)**:
  * 모바일 웹 브라우저(Safari, Chrome) 및 PWA 샌드박스 환경에서는 카카오톡의 특정 개인 채팅방 또는 비인가 단체 카톡방으로 텍스트를 백그라운드에서 직접 주입·자동 전송하는 기능이 카카오 공식 보안 정책(Cross-Origin/Deep Link 스팸 방지 규정)상 **원천 차단**되어 있음.
  * 카카오 JavaScript SDK의 `Kakao.Share.sendDefault`는 카카오톡 내 '친구/채팅방 선택기 모달'을 매번 띄우므로, 운행 중인 드라이버가 거치대에서 여러 번 탭해야 하는 인지 부하가 발생함.
- **실무 최적화 파이프라인 구축**:
  1. **초고속 동기 복사**: 버튼 터치 이벤트 핸들러 시작 즉시 0.05초 이내에 동적 완성된 보고 문구를 클립보드에 동기(`navigator.clipboard.writeText`) 복사하여 iOS Safari의 User Gesture 보안 기준 완벽 충족.
  2. **즉각적인 앱 포그라운드 전환**: 클립보드 복사 직후 `kakaotalk://` URL 스킴을 호출하여 카카오톡 앱을 전면 실행.
  3. **설정창 내 단톡방 메모 관리**:
     * `ProfileModal.tsx`에 `고정 보고 단톡방 / 수신자 메모`(`targetChatRoom`, 기본값: `VIP 의전 단톡방`) 입력 필드를 신설하고 `localStorage`에 자동 영속화.
  4. **인지 부하 최소화 토스트 피드백**:
     * 클립보드 복사 시 토스트 메시지로 `📋 복사 완료! [{설정된 단톡방명}]에 바로 붙여넣기 하세요.`를 명확히 안내하여, 드라이버가 카카오톡 실행 후 망설임 없이 해당 단톡방에 진입하여 '붙여넣기 + 전송' 1회로 보고를 마칠 수 있도록 최적화.

## 4. 실기기 운행 테스트 가이드 (Driver Cockpit Verification)

1. **설정창 티맵 로고 & 대칭 점검**:
   - 우측 상단 톱니바퀴 아이콘 터치 → 프로필 모달 오픈.
   - 내비게이션 3종 중 '티맵' 버튼이 깨끗한 화이트 원형 배경에 신규 BI 그라데이션 'T' 로고로 표시되는지 확인.
   - 'T' 로고 상단 가로 바의 좌우 날개 폭과 두께가 완벽한 대칭을 이루는지 확인.
2. **고정 단톡방 메모 설정**:
   - 프로필 모달의 `고정 보고 단톡방 / 수신자 메모` 필드에 운행할 단톡방명(예: `의전 1팀 단톡방`) 입력 후 [설정 저장].
3. **출발지/목적지 변경 및 실시간 ETA 동적 반영 점검**:
   - [출발지] 카드 탭 후 거점 칩(예: [신라호텔]) 선택 → 거리 및 소요시간 즉각 갱신 확인.
   - [목적지] 카드 탭 후 거점 칩(예: [인천공항 T2]) 선택 → 실시간 이동거리와 소요시간이 즉시 재계산되는지 확인.
   - 중앙 **[⇄]** 버튼 터치 시 출발지와 목적지가 즉시 교환되며 반대 방향 경로 및 ETA가 실시간으로 재계산되는지 확인.
4. **카카오톡 단톡방 보고 원터치 파이프라인 확인**:
   - 하단 노란색 `[카카오톡 단톡방 보고]` 버튼 터치.
   - 하단 토스트에 `📋 복사 완료! [의전 1팀 단톡방]에 바로 붙여넣기 하세요.`가 출력되고 즉시 카카오톡 앱이 실행되는지 확인.
   - 카카오톡 단톡방 입력창에 길게 눌러 붙여넣기 시, 선택된 출발지·목적지·실시간 거리·소요시간·정확한 한국 현지 ETA 시각이 그대로 붙여넣어지는지 확인.
