# 영수증 전문 검수: 수정 저장 → 원본 대조 → 승인 후 다음

기존 `HqExpensesView`와 `/api/expenses`를 확장했다. PC에서는 원본과 항목을 좌우로 비교하고, 작은 화면에서는 원본과 항목이 세로로 이어진다. 원본 확대·회전·화면 맞춤은 미리보기에만 적용한다.

## 저장과 승인

- 상호·날짜·시간·항목·금액·결제수단·주소·메모·연결 예약, 검수 의견과 청구 구분을 수정한다. 원본 경로·OCR·기사·차량은 이 검수 요청으로 변경할 수 없다.
- 항목 교정은 승인과 별도로 저장한다. 교정된 내역은 검수 대기로 돌아가고 이전 검수자·승인 시각을 비운다. 변경 전후 값, 서버 계정 ID와 시각을 감사 이력에 남긴다.
- 예약 변경은 같은 조직·기사·차량의 배정된 예약만 허용한다. 예약/날짜 변경 시 기존 운행일지 연결을 해제하고 DB 트리거가 정확한 새 일지에 연결해 양쪽 집계를 갱신한다.
- 미저장 수정·새 서버 버전·원본 로딩 실패·미확정 금액/항목/결제수단은 승인을 막는다. 원본 대조 체크 후에만 승인하며, 입력 영역 밖에서 Ctrl/Cmd+Enter를 지원한다.
- 서버가 요청 값과 새 버전을 확인한 경우에만 저장 결과를 채택한다. 실패·동시 수정 시 입력을 유지하며 다음 건으로 이동하지 않는다. 20초 조회가 오래된 행으로 확정 저장을 되돌리지 않게 한다.
- 승인 후 목록을 재조회해 현재 필터의 순서대로 다음 대기/금액확인 건을 연다. 목록 재조회 실패는 현재 건이 승인됐다는 안내와 함께 화면에 남긴다. 이미 승인·반려·삭제된 건은 건너뛴다.

## SQL 적용 전

`20261102001414_receipt_review_integrity.sql`은 **운영 미적용 제안**이다. 선행 보고 스키마를 확인한 뒤 기존 중복 승인 원본과 증빙/필수값이 부족한 승인 내역을 먼저 확인해야 한다. 중복 기록을 자동 삭제하거나 원본을 덮어쓰지 않는다. 같은 조직·같은 원본 경로의 중복 승인은 고유 인덱스로 막고, 필수값 없는 승인은 DB 트리거로도 거절한다. 일반 클라이언트의 직접 함수 호출 권한을 부여하지 않는다.

`supabase/checks/release_preflight.sql`에는 새 고유 인덱스 유효성과 승인 트리거 활성 여부를 읽기 전용으로 추가했다. 이것은 운영 출시 승인이나 모든 기존 데이터의 적합성 검사를 뜻하지 않는다.

## 이번 재개에서 확인한 범위

- 최신 공유 브랜치 `44e8523`의 기사 로그인/HQ 로그인 통합 변경을 보존했다.
- 44개 단위 테스트 파일, TypeScript, 프로덕션 빌드, 프로덕션 HTTP smoke와 신규 검수 모듈 ESLint가 통과했다. 번들 게이트 상태 조회는 수행하지 않았다.
- PostgreSQL 18.3 / PGlite 0.5.8의 격리 엔진에서 실제 API 핸들러·클라이언트 저장 함수와 SQL을 실행했다. 수정 전후/계정 이력, OCR·원본 보존, 금액/날짜 변경 집계 재연결, 수정과 승인 분리, 같은 원본 중복 승인 차단, 다른 차량 예약 연결 차단, SQL 두 번 적용과 직접 클라이언트 권한 거절을 확인했다.
- 이 검사는 **단일 WASM 엔진에서 직렬화한 검사**다. 테스트 로그에 기존 독립 연결/동시성 문구가 있더라도 실제 독립 PostgreSQL 연결의 동시성 검증을 대신하지 않는다. 실제 서버의 `npm run test:db`와 CI는 아직 실행하지 못했다.
- 연결된 브라우저와 클라우드 브라우저 모두 이 실행 환경의 localhost에 연결되지 않았다. 이번 화면의 모바일·PC 브라우저 검수는 미완료이며, 실물 영수증 OCR 정확도도 확인하지 않았다.
- 코드 변경은 로컬 커밋으로 보존했다. 처음 원격 푸시는 자동 승인 검토가 거절했으나, 이후 사용자가 작업 완료 시 항상 GitHub에 푸시하도록 명시적으로 승인했다. 기존 PR #40 브랜치에 반영하는 범위이며 main 병합·운영 SQL 적용·배포·고객 발송은 수행하지 않았다.

사용자의 원격 반영 승인에 따라 기존 PR #40 브랜치에 반영하고 실제 PostgreSQL CI를 확인한다. 개발 서버에 접근 가능한 브라우저에서 390px/1280px 원본 비교·입력 보존·충돌·승인 후 다음 이동을 검수한다. 이후 실제 기사 계정 매핑과 업무 한 건의 운영 검수를 거쳐 푸시/Info 실제 전달 및 차량·현장 팁 공유 저장을 진행한다.
