# PWA 계정별 시작 화면

기존 PR #40의 대표 로그인·모바일 HQ와 기사 콕핏을 재사용한다. 별도 PWA, Vercel 프로젝트, 대표 전용 배차 DB를 만들지 않는다. 작업 기준 원격 HEAD는 `6f06ad991d0c218edac654f0eda3291fe6af5411`이다.

## 실행 흐름

`public/manifest.json`의 `start_url: "/"`와 기존 앱 이름/아이콘을 유지한다. 기존에 설치한 아이콘의 시작 경로도 서버의 같은 분기를 거친다.

| 인증된 계정 | 기본 화면 |
| --- | --- |
| HQ 권한 + 서버 관리 대표 표시 | `/representative` |
| 일반 HQ | `/hq?tab=dashboard` |
| 기사 | `/`의 기존 콕핏 |
| 미인증 / 철회된 세션 | `/login` |

`app/page.tsx`는 동적 서버 진입점이다. 쿠키와 실제 Auth 사용자를 검증한 다음 대표·관리자를 전용 경로로 보낸다. 기사가 확인된 경우에만 기존 작성기/운행 화면을 포함한 `DriverCockpit`을 표시한다. 기존 화면은 클라이언트 컴포넌트로 옮겨 그대로 재사용한다.

접근 토큰이 만료됐지만 갱신 쿠키가 있으면 `/api/auth/launch`에서 기존 세션 핸들러로 갱신한다. 회전된 HttpOnly 쿠키를 유지하고 계정별 화면으로 이동한다. 인증 실패/철회 시 쿠키 삭제도 전달한다. 리다이렉트는 고정된 앱 내부 상대 경로만 사용하므로 원래 접속 호스트가 바뀌지 않는다. `next` 쿼리로 외부 주소를 주어도 사용하지 않는다. 응답은 `private, no-store`와 `Vary: Cookie`를 적용한다.

로그인 복귀 주소가 `/`인 경우도 기사 화면을 우선 열지 않고 계정 기본 화면으로 바로 보낸다. 명시적인 권한 있는 HQ 내부 주소 등 기존 복귀 링크는 유지한다.

앱/탭 복귀의 `pageshow`, 포커스, 온라인, 화면 재표시에서는 서버 세션을 다시 확인한다. 이때 짧은 클라이언트 캐시를 건너뛰되 동시 요청은 합친다. 루트에 복원된 대표/HQ 세션은 전용 화면으로 교체한다. 브라우저 저장값에 대표 표시를 넣어도 서버 권한은 바뀌지 않는다.

## 지정 계정 연결

사용자가 지정한 이메일의 기존 Auth 계정 1개를 확인한 뒤, 해당 계정에만 `org=vip_limousine_korea`, `cockpit_role=hq_admin`, `cockpit_position=representative`를 서버 관리 메타데이터로 연결했다. 다른 메타데이터는 보존했다. 별도 조회에서 대표 연결, 기존 이메일 인증 상태, 비밀번호 존재를 확인했다. 비밀번호 변경·계정 재생성·초대 발송은 하지 않았다. 이메일 주소를 소스 코드의 권한 허용 목록으로 넣지 않는다.

이는 계정 권한 준비 완료이며 운영 출시 완료는 아니다. 운영 프로젝트의 `cockpit.is_active_auth_session(uuid,uuid)`는 아직 설치되지 않은 것을 읽기 전용으로 확인했다. 기존 개인 인증 SQL의 적용과 이 코드 배포를 함께 진행해야 실제 신규 로그인 흐름이 작동한다. 현재 운영 코드와 충돌할 수 있는 공용 DB 스키마 변경이나 main 병합·배포는 수행하지 않았다.

## 검증

- `npm test`: 40/40 테스트 파일 통과. 계정별 기본 주소, 루트 로그인 복귀, 인증 실패, 갱신/삭제 쿠키, 캐시 비공개 응답, 복귀 시 강제 권한 재조회 포함.
- TypeScript와 프로덕션 빌드 통과. 새 서버 진입점/라우트/헬퍼/단위 테스트 대상 ESLint 오류 없음. 전체 레거시 lint 통과를 의미하지 않는다.
- 프로덕션 HTTP smoke에서 실제 Next 서버·Auth 핸들러와 격리 인증 제공자를 사용해 대표/HQ/기사 루트 분기, 만료 토큰 갱신, 철회된 세션 거절, 기존 대표 보호 경로, 원래 PWA 시작 주소 유지 검사 통과.
- Chromium의 iPhone 크기/UA 및 Android 크기/UA 프로필에서 세 역할의 루트 실행과 창 재열기, 로그인 POST 없는 재접속을 검사했다. 대표/HQ 진입 시 기사 메뉴가 잠깐이라도 생성되는지 관찰해 생성되지 않음을 확인했다.
- 브라우저 전체 종료 후 저장한 쿠키 상태로 재실행, 만료된 대표 접근 토큰의 갱신, 브라우저 저장값 위조가 무시되는지, 서버 권한 변경 후 `pageshow`에서 캐시를 건너뛰어 대표 화면으로 이동하는지 확인했다.
- 브라우저 테스트의 인증 제공자와 일정/보고 API는 격리 fixture다. 실제 iOS Safari·Android Chrome 설치형 PWA/물리 기기 검수는 수행하지 않았으며, UA/화면 크기 검사를 실제 단말 테스트로 간주하지 않는다.

## 운영 반영 후 단말 확인

같은 HTTPS 운영 주소와 Auth 프로젝트를 사용한다. 기존 개인 인증 스키마와 이번 통합 브랜치를 반영한 뒤 다음을 확인한다.

1. iPhone 홈 화면 앱 및 Android 설치 앱 안에서 지정된 대표 계정으로 로그인한다.
2. 앱 종료 후 아이콘으로 다시 열어 대표 대시보드로 진입하고 배정 작업을 수행한다.
3. 세션 만료/철회 후에는 로그인 화면으로, 로그인 성공 후에는 대표 화면으로 복귀하는지 확인한다.
4. 일반 HQ와 개별 기사 계정도 같은 아이콘에서 각 화면으로 분기하는지 확인한다.

공용 비밀번호, 사용자 수정 가능 메타데이터, 로컬 저장값으로 대표 권한을 부여하지 않는다. 원래 대표의 이메일이 확정되면 해당 개인 계정으로 서버 권한 연결을 조정한다.
