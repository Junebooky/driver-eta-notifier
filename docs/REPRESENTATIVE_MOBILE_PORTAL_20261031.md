# 대표 전용 로그인과 모바일 관제

기존 Supabase 개인 계정·HQ API·배차 저장·차량 상태·기사 확인을 확장한다. 대표용 별도 배차 DB나 별도 비밀번호 저장소를 만들지 않는다. 기준 원격 HEAD는 `bbb646bc37881ba9f33e8059de4ffdba80f370ff`이며, 기존 PR #40 위에서 작업한다.

## 로그인과 계정 연결

- `/representative/login`: 대표 전용 이메일/비밀번호 로그인. 기존 인증 앱 번호(TOTP)도 유지한다.
- `/representative`: 서버에서 실제 세션과 대표 권한을 확인하는 모바일 대시보드. 일반 관리자와 기사 계정은 전용 로그인으로 돌려보낸다.
- 접근 토큰이 만료돼도 유효한 갱신 쿠키가 있으면 기존 세션 갱신 핸들러를 거쳐 대표 화면으로 복귀한다. 매번 비밀번호를 다시 입력하지 않는다.
- 일반 `/login`에서도 기사·관리자·대표 진입을 선택할 수 있다. 대표는 기본적으로 `/representative`, 일반 관리자는 `/hq?tab=dashboard`로 진입한다.
- 로그인 구분은 접근 의도일 뿐 권한을 부여하지 않는다. 서버가 조회한 Auth `app_metadata`만 권한을 결정한다. 사용자 수정 가능 `user_metadata`나 요청 본문의 대표 표시를 신뢰하지 않는다.

운영 Auth의 메타데이터를 읽기 전용으로 확인한 결과, 현재 새 방식으로 연결된 HQ 계정과 대표 계정은 각각 0개였다. 실제 계정 활성화 완료로 간주하지 않는다.

실제 대표의 기존 개인 Auth 계정에 운영자가 다음 서버 관리 값을 지정해야 한다. 기존 다른 메타데이터는 보존한다.

```json
{
  "org": "vip_limousine_korea",
  "cockpit_role": "hq_admin",
  "cockpit_position": "representative"
}
```

대표의 서버 권한은 기존 HQ 권한을 재사용하고 세션에 `isRepresentative`를 추가한다. 별도 공용 PIN이나 고정 비밀번호를 만들지 않는다. 실제 대표 이메일/계정 정보가 제공되지 않아 운영 계정 생성·메타데이터 변경·초대 전송은 수행하지 않는다. 기존 개인 계정/DB 출시 계획의 배차·인증 스키마가 운영에 준비돼야 한다.

## 모바일 배차

- 대시보드에서 배차 대기·오늘 일정·기사 미확인·재확인 건수를 조회하고 해당 목록으로 바로 이동한다.
- 휴대폰·태블릿의 예약 목록은 일정 카드로 표시한다. 날짜/시간, 출발·도착지, 실제 차량, 기사, 확인 상태가 한 카드에 모인다.
- 차량·기사 배정 버튼은 기존 예약 상세 모달의 배정 화면을 먼저 연다. 예약 정보와 배정을 전환해도 입력을 유지한다. 종료 시간이 없는 일정은 예약 정보에서 확인하도록 안내한다.
- 차량·기사 목록은 기존 실제 가용성 API를 사용하며 가용 대기 차량 우선과 충돌 차단을 유지한다. 확정은 기존 멱등 배차 API를 호출한다.
- 모바일 모달은 화면 높이에 맞추고 내용 영역만 스크롤한다. 큰 선택 영역, 하단 안전영역, 입력 시 iOS 자동 확대를 줄이는 글자 크기를 반영한다.
- 하단 메뉴는 대시보드·배차·차량·빠른예약·전체메뉴를 제공한다. 경비·일지·이메일 등 기존 메뉴도 전체메뉴로 접근한다.
- 누적 보고 요약은 대시보드에서 확인한다. 다른 화면마다 요약 카드가 위를 차지하던 부분을 정리했다. PC는 기존 표와 전체 메뉴를 유지한다.

## 추가 결함 수정

1. 서버에 저장된 `end_date`·`end_time`이 ScheduleItem 응답 변환에서 누락됐다. 실제 종료 날짜·시간을 응답과 HQ 예약 편집기로 보존해 다시 입력하지 않고 가용성을 조회하도록 수정했다.
2. 자동 갱신 때 열린 예약 객체가 바뀔 때마다 편집 입력이 초기화됐다. 편집기 최초 기준을 유지하고 기사 확인 표시는 최신 서버 조회를 반영한다.
3. 다른 기기에서 변경한 배차를 오래된 입력으로 저장할 수 있었다. 최초 `expectedVersion`을 저장 API까지 전달하고 서버에서 오래된 버전을 409로 거절한다. 편집 중 새 버전이 조회되면 입력을 보존하고 재열기를 안내한다. 저장 조회~트랜잭션 사이의 기존 DB CAS 보호도 유지한다.
4. 사이드바가 차량/기사/대시보드에서도 예약·배차 메뉴를 동시에 선택 표시하던 조건을 수정했다. 하단 메뉴 이동 시 오래된 검색·KPI 필터도 초기화한다.
5. 기사 전용 권한 검사에서 HQ 역할이 예외로 통과할 수 있던 공통 검증 조건을 수정했다.

## 검증 범위

단위 테스트는 대표 권한 위조 차단, 로그인 복귀 경로, 기사 전용 권한 검사, 오래된 배차 수정 거절, 저장된 자정 넘김 종료 일시의 API→HQ 보존을 포함한다. 프로덕션 HTTP smoke는 실제 인증 핸들러와 격리 인증 제공자를 연결해 대표 로그인·쿠키·서버 보호 경로 및 일반 HQ 거절을 검사한다.

실제 Postgres CI 통합 테스트에 일정 API의 종료 일시 보존과 HTTP 배차 API의 오래된 수정 409/기존 버전 유지 검사를 추가한다. 로컬 `npm test` 39/39 파일, TypeScript, production build 및 HTTP smoke를 통과했다.
