# 첨부 일정 분석 누락 방지

기준: integration/driver-cockpit-20261104 / 9f526c4.

## 확인한 기존 연결

HQ 분석 버튼 → extract-booking 서버 → 인증된 IMAP 원문과 실제 첨부 → Excel/Word 텍스트 + PDF 원본 inlineData → Gemini가 이미 연결돼 있었다. 본문도 일부만 잘라 보내지 않는다. 기능 부재로 진단하면 안 된다.

선택된 전달 메일을 사용자 브라우저에서 분석해, 두 Excel 첨부가 표시되지만 첫날의 출발/도착만 나타나는 현상을 확인했다. 첨부 미리보기는 가로 날짜·세로 시간·병합 일정 블록 형식이었다. UI 관찰만으로 해당 실행의 실제 서버 입력이나 모델 원시 출력을 확정하지는 않았다. 실제 메일 내용과 파일 원본은 저장소/테스트에 포함하지 않았다.

## 변경

- Excel의 전체 시트, 원래 셀 주소와 병합 범위를 전달한다. 빈 워크북과 과도한 셀은 조용히 잘라 보내지 않고 명시적으로 거절한다.
- Date 행/열의 명시적인 날짜 라벨과 비어 있지 않은 시트 목록을 문서 목록으로 전달한다. 제목의 기간을 매일 운행으로 확장하지 않는다.
- Gemini 응답은 문서별 sourceId, 검토 시트, 실제 일정 날짜를 반환한다. 문서/시트 누락 및 표 날짜/모델이 보고한 날짜가 경로에서 사라지면 실패로 반환한다. 본문 보정으로 누락을 가리기 전에 확인한다. 빈 날짜 열이나 취소된 날짜 등 자동 판정이 모호한 자료도 관리자가 확인할 수 있도록 분석 실패할 수 있으며, 해당 날짜 운행을 생성해 통과시키면 안 된다.
- 첨부가 있을 때 전체 인용 본문을 정규식으로 다시 경로에 합치지 않는다. 최신 첨부를 기준으로 과거 제안을 정리하는 것은 모델에 맡기고, 불확실성은 경고로 보존한다.
- 서버가 읽은 메일 작성 시각을 기준으로 날짜를 해석하고 인용 메일은 해당 메시지 작성일을 쓰도록 지시한다.
- 파일명/크기가 같아도 내용이 다른 수정본을 제거하지 않는다. 동일한 바이트만 중복 제거한다.
- 성공한 초안에 검토한 파일/시트 정보를 저장하고 공통 HqInlineFeedback으로 표시한다. 재분석 실패 후 과거 초안이 그대로 확정되지 않도록 재분석 시작 시 이전 초안을 비운다.

## 검증과 범위

- 117개 테스트 파일 통과. 신규 7개 회귀는 달력형 2개 Excel, 다중 시트, 병합 셀, 원본 PDF, 같은 크기 수정본, 빈/긴 셀, 첫날만 반환하는 응답을 포함한다.
- 실제 Gemini 서비스의 HTTP 전송을 합성 응답으로 대체해 두 Excel과 PDF 원본이 한 요청에 포함되는지, 부분 결과가 실패하는지, 전체 결과가 성공하는지 검사했다. 외부 AI 호출 없이 검증한다.
- TypeScript 및 프로덕션 빌드 통과. 최종 CI/HTTP 결과는 PR 기록 참조.
- 이 패치를 사용자의 로컬 서버에 설치해 실제 메일을 재분석한 것은 아니다. 실제 모델의 결과 품질과 모든 PDF 날짜를 독립적으로 보장하는 검증은 아니다. PDF는 모델이 보고한 날짜를 대조한다.
- 별도 메일의 옛 첨부를 자동 수집하는 기능이나 차량별로 다른 경로를 자동 배차하는 기능은 추가하지 않는다. 기존 개별 경로의 관리자 확인 차단을 유지한다.
- 이 작업 브랜치의 Vercel 자동 배포를 비활성화했다. 메일 발송·예약 확정·운영 DB 변경은 하지 않았다.
