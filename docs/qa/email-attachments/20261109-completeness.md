# 첨부 일정 분석 누락 방지

기준: integration/driver-cockpit-20261104 / 9f526c4.

## 확인한 기존 연결

HQ 분석 버튼 → extract-booking 서버 → 인증된 IMAP 원문과 실제 첨부 → Excel/Word 텍스트 + PDF 원본 inlineData → Gemini가 이미 연결돼 있었다. 본문도 일부만 잘라 보내지 않는다. 기능 부재로 진단하면 안 된다.

선택된 전달 메일을 사용자 브라우저에서 분석해, 두 Excel 첨부가 표시되지만 첫날의 출발/도착만 나타나는 현상을 확인했다. 첨부 미리보기는 가로 날짜·세로 시간·병합 일정 블록 형식이었다. UI 관찰만으로 해당 실행의 실제 서버 입력이나 모델 원시 출력을 확정하지는 않았다. 실제 메일 내용과 파일 원본은 저장소/테스트에 포함하지 않았다.

## 변경

- Excel의 전체 시트, 원래 셀 주소와 병합 범위를 전달한다. 빈 워크북과 과도한 셀은 조용히 잘라 보내지 않고 명시적으로 거절한다.
- Date 행/열의 명시적인 날짜 라벨과 비어 있지 않은 시트 목록을 문서 목록으로 전달한다. 제목의 기간을 매일 운행으로 확장하지 않는다.
- Gemini 응답은 문서별 sourceId, 검토 시트, 실제 일정 날짜를 반환한다. 문서/시트 자체 누락은 실패로 반환한다. 표 날짜/모델이 보고한 날짜가 경로에서 사라지면 초안에 확인 필요 날짜로 보존한다. 원본·필요 일정 검토를 명시적으로 확인하기 전에는 예약 확정과 단일/일괄 배차를 막는다. 빈 날짜 열이나 취소된 날짜에 운행을 임의 생성하지 않는다.
- 첨부가 있을 때 전체 인용 본문을 정규식으로 다시 경로에 합치지 않는다. 최신 첨부를 기준으로 과거 제안을 정리하는 것은 모델에 맡기고, 불확실성은 경고로 보존한다.
- 서버가 읽은 메일 작성 시각을 기준으로 날짜를 해석하고 인용 메일은 해당 메시지 작성일을 쓰도록 지시한다.
- 파일명/크기가 같아도 내용이 다른 수정본을 제거하지 않는다. 동일한 바이트만 중복 제거한다.
- 성공한 초안에 검토한 파일/시트 정보를 저장하고 공통 HqInlineFeedback으로 표시한다. 재분석 실패 후 과거 초안이 그대로 확정되지 않도록 재분석 시작 시 이전 초안을 비운다.

## 검증과 범위

- 117개 테스트 파일 통과. 신규 7개 회귀는 달력형 2개 Excel, 다중 시트, 병합 셀, 원본 PDF, 같은 크기 수정본, 빈/긴 셀, 첫날만 반환하는 응답을 포함한다.
- 실제 Gemini 서비스의 HTTP 전송을 합성 응답으로 대체해 두 Excel과 PDF 원본이 한 요청에 포함되는지, 부분 결과가 실패하는지, 전체 결과가 성공하는지 검사했다. 외부 AI 호출 없이 검증한다.
- TypeScript 및 프로덕션 빌드 통과. 최종 CI/HTTP 결과는 PR 기록 참조.
- 이 패치를 사용자의 로컬 서버에 설치해 실제 메일을 재분석한 것은 아니다. 실제 모델의 결과 품질과 모든 PDF 날짜를 독립적으로 보장하는 검증은 아니다. PDF는 모델이 보고한 날짜를 대조한다.
- 별도 메일의 옛 첨부를 자동 수집하는 기능이나 차량별로 다른 경로를 자동 배차하는 기능은 추가하지 않는다. 기존 개별 경로의 관리자 확인 차단을 유지한다.
- 이 작업 브랜치의 Vercel 자동 배포를 비활성화했다. 메일 발송·예약 확정·운영 DB 변경은 하지 않았다.

## 11월 14일 422 회귀 수정

기존의 날짜 불일치 예외가 분석 전체를 실패시켰다. 이 경우에는 읽힌 초안을 반환하고 파일별 missingDates와 검토 완료 상태를 보존한다. 공통 HqInlineFeedback/HqButton으로 확인 날짜와 원본 대조·필요 경유지 추가를 안내한다. 확인을 취소하면 다시 예약 확정/배차가 차단된다. 재분석은 확인 상태를 초기화한다. 파일/시트 입력 누락은 여전히 실패 처리한다.

추가 회귀는 11/14만 빠진 결과를 초안으로 반환하는지, 검토 전 단일/일괄 배차가 차단되는지, 검토 완료와 취소가 동작하는지 확인한다. 실제 SDK 서비스의 합성 응답과 1280/390px UI에서도 검증한다. 실제 메일을 새 코드로 재분석한 것은 아니다.


## 11월 11일 단일 날짜 내 다중 일정 누락 방지 — Calendar cell reconciliation

A02 PR #86/#87의 파일/시트/날짜 커버리지 체크만으로는 같은 날짜의 5개
약속 중 1개만 반환한 Gemini 응답을 잡을 수 없었다.

- 달력형 엑셀의 날짜 열 × 시간 행에서 **비어 있지 않은 일정 셀 1개 = 원본 일정 1건**으로 읽는다.
  병합된 셀은 앵커만 보존, 시간은 문구의 명시 시각을 우선하고 없으면 원본 시간표 행을
  사용하되 실제 차량 출발 시각으로 추정하지 않는다.
- 원본 셀 주소, 원문, 고객 제공 주소, 날짜/시각을 파일별로 남긴다. 단일 엑셀
  일정은 Gemini 결과와 비교해 누락된 셀을 AI 상세 일정(waypoints)에 추가한다.
  **TMAP 주소/좌표는 자동 확정하지 않는다.**
- 클라이언트가 도로명 주소를 쓰지 않은 일정은 삭제하지 않고
  '클라이언트측 주소 미지정'과 'TMAP 위치 미확정'을 별도로 표시한다.
  원본 표의 첫/마지막 이벤트는 차량 출발/종료로 단정하지 않는다.
- **서로 다른 첨부파일/시트(차량) 일정은 합쳐서 한 차량 경로로 만들지 않는다.**
  원본 전체 항목은 파일별 상세 대조 패널에 보이고 분리 검토 안내를 남긴다.
  같은 이름·바이트 크기인 수정본도 원본별로 구분한다.
- 부분 수정 메일에서 이전 첨부 내용을 기준으로 확정된 변경사항을 되돌리지 않는다.
- 기존의 날짜/시트 커버리지 검사 및 미확정 위치 배차 차단은 유지한다.
- 사용자 원본 파일/실제 고객 자료는 저장소에 커밋하지 않는다. 재현 테스트는
  합성 일정표를 사용한다. Live Gemini/IMAP 실제 분석과 운영 DB 쓰기는 하지 않는다.
