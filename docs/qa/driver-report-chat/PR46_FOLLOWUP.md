# PR #46 병합 전 보완

PR #45 최신 4개 커밋 `5e9c681`, `ce7157b`, `603ef33`, `349de9f`를 병합했습니다. 기존 기사 PWA와 HQ 동작은 보존합니다.

## P0: 활성 장부 연도

연도가 없는 보고는 활성 연간 장부의 파일명에 명시된 단일 연도를 사용합니다. 파일명에 연도가 없으면 월 시트 A열의 기록에서 단일 연도가 확인될 때 사용합니다. 레거시 A1 숫자 제목은 제외합니다. 연도가 불명확하거나 여러 해가 섞인 장부만 확인 대상으로 둡니다. 등록 시 연도를 식별할 수 없는 파일은 연도 명시를 요구합니다. 정상 2026 장부의 `10월 24일(토)`는 관리자 확인 없이 자동 반영됩니다. 서버의 현재 연도와 달라도 활성 장부 연도가 우선합니다. 처리 도중 활성 장부 연도와 제출 연도가 다르면 다른 연간 장부에 쓰지 않습니다.

## 운영 설정

`REPORT_NIGHT_END_HOUR`는 심야 종료 시각(정수 0~21, 기본 6)입니다. 시작은 22시이며 서버 환경 설정으로 변경 후 프로세스를 재시작합니다. 잘못된 값은 오류로 거절합니다. 종료 06시는 코드에 고정된 회사 정책이 아닌 초기 설정입니다. 이미 저장된 계산은 자동 재산정하지 않습니다. HQ 재검토는 현재 설정으로 계산하고 변경 이력을 남깁니다.

## 실사용 E2E

`scripts/qa-yearless-chat.mjs`는 격리 localhost 전용입니다. Playwright와 Chromium, Next + PostgreSQL/PostgREST 테스트 서버, 기사 윤태준/HQ 격리 세션 JSON, 승인된 `10월` 시트가 있는 2026 장부를 준비합니다. 실제 회사 장부나 세션 값을 저장소에 넣지 않습니다.

실행 변수: `REPORT_CHAT_QA_URL`, `REPORT_CHAT_QA_TOKENS`, `REPORT_CHAT_QA_WORKBOOK`, 선택 `PLAYWRIGHT_MODULE`, `CHROMIUM_PATH`, `REPORT_CHAT_QA_OUTPUT`. 실행 명령 `node scripts/qa-yearless-chat.mjs`.

검증 통과: 연도 없는 실제 카카오톡 예시 → `700호 1458 / 스프린터 319` → 모든 반복 경유지 유지 → 기존 10월 시트 반영 → 채팅 완료 답장 → 재접속 이력 복원. 두 번째 `10:00~24:00` 보고는 `OT 2시간 / 심야 2시간`. 재전송 멱등성도 통과했습니다. 시험용 10월 템플릿에 자동 누적한 결과를 ZIP/XML 비교해 기존 모든 기록/서식/다른 문서가 그대로이고 새 두 행과 사용 범위만 변경됨을 확인했습니다. 실제 회사 파일에 없는 10월 시트를 임의로 만들었다고 주장하지 않습니다.

## DB 용량·백업 검토

- 파일 전체 bytea 버전은 원본+성공 반영마다 1개입니다. 대략 `연평균 작업본 크기 × 보고 건수`입니다. 평균 1MB × 일 100건 × 365일이면 약 36.5GB/년(원본, WAL, PITR, 스냅샷 비용 제외); 5MB면 약 182.5GB/년입니다. 실제 크기/건수 계측과 예산 확정이 운영 전 필요합니다.
- 원본과 활성 버전, 제출의 applied_version, 복구 manifest 및 감사 이력이 참조하는 버전을 임의 삭제하면 안 됩니다. 현재 자동 삭제/압축 정책은 구현하지 않았습니다. 제안 정책: 최근 30일 모든 성공 버전, 이후 일별/월별 보관을 검토하되 참조 재구성·복구 검증을 먼저 설계해야 합니다. 아직 적용된 정책이 아닙니다.
- DB 일일 백업과 PITR, 별도 암호화된 오프사이트 장부 백업을 함께 검토하고 복구 훈련으로 원문/대화/활성 파일/manifest 일관성을 확인해야 합니다. RPO/RTO, 보존 기간, 접근 권한은 회사 승인 사항입니다. PostgreSQL bytea는 대규모 운영 전에 private object storage 불변 객체+트랜잭션 포인터로 분리하는 것을 권장합니다.
- 배포 플랫폼 업로드/응답 크기 제한, DB/WAL 증가량, 백업 저장료를 모니터링해야 합니다. 운영 백업 또는 DB 설정을 직접 변경하지 않았습니다.
