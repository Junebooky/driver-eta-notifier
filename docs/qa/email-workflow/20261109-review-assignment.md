# 이메일 예약 검토·차량 선택 수정

기준: 최신 통합 브랜치 `integration/driver-cockpit-20261104`의 `ff522dc`. 기존 HQ A안 토큰과 `HqModal`, `HqInput`, `HqSegmentedTabs`, `HqBadge`, `HqButton`, `HqCard`, `HqInlineFeedback`을 사용한다.

## 변경

- 차량창은 공용 등록부(`useHqFleetRegistry`)와 일정 가용성을 분리한다. 종료시간 미입력이나 가용성 조회 실패도 등록 실차를 숨기지 않는다. UUID와 번호판이 모두 일치하는 최신 결과만 배정 가능으로 처리한다. 등록부에 없는 차량을 옛 가용성 응답/하드코딩 목록으로 복원하지 않는다. 미확인·정비·충돌 차량은 사유를 표시하고 선택을 막는다. 검색/분류는 같은 창의 갱신 중 유지되며 새로 열 때 초기화한다.
- 시작·종료 시간 누락/역전은 가용성 훅에서 설명한다. 전체 차량 표시를 예약 가능 판정으로 오인하지 않는다. 예약 가능한 대기 차량을 먼저 정렬한다.
- 3단계 경유지·출발/도착지와 5단계 주소 미확정 상태를 공통 `HqBadge`의 warning 톤으로 통일한다. 제공 주소가 있더라도 TMAP 위치 미확정을 숨기지 않는다.
- 고객 제공 주소의 ‘원문에서 확인’은 `HqSourceText`에서 실제 본문의 일치 부분 전체를 강조하고 첫 위치로 스크롤/포커스를 옮긴다. 대소문자·유니코드 폭·공백/줄바꿈 차이만 허용한다. 원문에 없으면 첨부/다른 표현 확인을 안내하며 추정 강조하지 않는다. 원본 문자열과 안전한 텍스트 렌더링을 유지한다. 본문 일치는 TMAP 위치 확정과 별도다.
- 4단계는 공통 `HqStaggeredReveal`로 체크→제목→설명→예약 정보→배정 안내 순서로 위에서 아래로 나타난다. 같은 초안에서 본 화면으로 돌아오면 정적 표시하고 기존 가로 슬라이드도 제거한다. 모션 감소 설정은 즉시 표시한다.

## 검증

- 단위 테스트 116개 파일, TypeScript, 깨끗한 프로덕션 빌드와 기존 실제 HTTP smoke 통과.
- 신규 회귀: 미확인 가용성에서도 등록부 표시, 등록부 밖/다른 UUID 결과 선택 차단, 대기 차량 우선 정렬, 반복 주소·공백·유니코드 원문 범위 보존과 불일치.
- `scripts/qa-email-workflow-ui.mjs`: 실제 Inbox와 하위 컴포넌트를 임시 Next 프로젝트에서 구동한다. 합성 메일/차량과 로컬 API만 사용하고 외부 요청을 차단한다. 1280px/390px에서 일치/불일치 원문, 경고 배지, 첫 진입/재방문, 종료시간 없는 차량 목록, 전체 보기·정비/충돌 선택 차단, 시간 수정 후 선택·검색 유지와 화면 넘침을 확인한다.
- 로컬 Chromium은 socket 권한 제한으로 실행되지 않았고 공유 브라우저도 명령 실행 환경의 localhost에 접근하지 못했다. GitHub의 별도 UI 회귀 workflow에서 실행한다. CI 결과와 스크린샷은 PR의 최신 검증 기록을 따른다.
- 이 수정 브랜치의 Vercel 자동 배포는 `vercel.json`에서 비활성화했다. Preview/운영 배포나 운영 DB·메일 변경은 하지 않는다.
