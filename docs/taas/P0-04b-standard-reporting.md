This proposal introduces a service-role-only transaction for standard report list/create (draft or submission) with fresh active session, membership, owned active driver, booking/date/vehicle/customer and linked driving log validation. The actor determines org and driver; admin may select an owned driver. IDs generated on server, no direct status override, client totals, arbitrary metadata, delete or upsert. Reuse existing reporting triggers and tables; no duplicate Excel writes. Receipt path helper checks canonical org/driver, month, digest and extension; actual receipt association is intentionally rejected until trusted storage object verification exists. No raw receipt paths, OCR details or card number returned in list. Existing APIs and UI unchanged. SQL remains review-only and runtime holds remain.

This is first-write/read only, not full replacement: retry/idempotency, draft updates and waypoint merge, approval/review CAS and audit, receipt object upload/download verification, Hi-Pass scoped dedup, custody mileage, canonical date/time validation and real API/UI mapping are remaining P0-04b tasks. Existing unique log key prevents duplicate log identity but expense retry can create duplicates, so no runtime activation. Existing direct RLS and RPC isolation, legacy ownership reconciliation, release and backup/restore gates remain. Tests temporarily activate synthetic tenants in rollback transaction and verify cross-company and same-company driver isolation, exact expense aggregation, path restrictions and unchanged legacy rows. No production migration or deployment.
