# P0-03e — Driver enrollment candidate (review only)

Parent #138 green, run 45763000052; Chauffeur main rechecked b801fe64680b7af5b95d8e4985da1ea9f7e9892f. Existing report-device invite is separate and stays unchanged.

Adds a new service-role-only invite store and transactional RPCs. Invitation is bound to the verified tenant, existing driver UUID and current enrollment email, expires in 24 hours, and stores only a SHA-256 token hash (not plaintext secret). Reissue invalidates unused invites. Redemption requires a separately provider-verified account and active session, exact verified email, correct tenant, and one-time token. No auto matching by name or phone, no existing membership overwritten. Creates pending driver membership only; company administrator separately approves. Revoke only the specific tenant membership; never delete global Auth, other memberships, existing profile or history. Profile deactivation additionally checks active/future/open schedules and unreturned custody. Both activation holds and runtime interlock remain intact. Tests simulate activation only in a rolled-back disposable transaction.

Limitations: this PR is DB candidate only, not email sending, account signup/password flow, public endpoint or HQ integration. Provider verification (including MFA), trusted host provenance, rate limiting, invite secret delivery, secure cookies, email ownership revalidation at approval, verified Auth mapping, re-enrollment of revoked profiles, self-service signup approval and full API isolation must be implemented before runtime is unlocked. No legacy user metadata or Supabase auth schema changes. No live DB writes, migrations or deployment. Existing global sessions remain valid for other memberships; per-tenant authorization must always recheck current membership. Historic and current records retained. No new tenant activation before P0 security and backup/restore gates.
